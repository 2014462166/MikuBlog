> 项目：[PixBead](https://github.com/2014462166/pixbead)。这篇只聊转化服务（Python + FastAPI + Pillow/NumPy）的部分。

## 转化流程总览

```text
1. 下载原图(OSS)
2. 预处理：EXIF 旋转 → 裁剪(可锁比例) → 去背景 → 锐化
3. 网格化：缩放到 grid_width × grid_height，逐格取平均色
4. 调色板：载入品牌色板，必要时先选子集
5. 色彩量化：格子颜色 → 色板色号
6. 抖动(可选)：量化前扩散误差
7. 渲染：圆豆 + 网格 + 色号标注
8. 导出：色号清单 / PDF
9. 写回 OSS，更新任务与作品
```

## 网格化：先决定“多少颗豆”

尺寸支持两种输入：直接给豆数，或给**板数**换算（比如经典 29×29 板 × 2×3）。定下 `grid_width × grid_height` 后，把图像缩放并**逐格取平均色**——这一步决定了图纸的“分辨率感”，太小糊、太大耗时。

## 色彩量化：三选一

把每个格子的 RGB 映射到色板，提供三种策略：

| 策略 | 特点 | 适用 |
| --- | --- | --- |
| 最近邻（CIE Lab） | 逐格找色差最小的色号，最快 | 默认，色板大时效果好 |
| 中位切分 | 按颜色分布切分，控制整体用色数 | 想要统一色调 |
| K-means | 聚出主色再映射，色数控制更自然 | 追求画面协调 |

关键细节：**色差在 CIELAB 空间算**，比直接比 RGB 更接近人眼感受，成品不会“灰一块紫一块”。

## 抖动：让渐变不出现色带

色板颜色有限时，大面积渐变很容易出现明显色带。可选的抖动算法：

- **Floyd–Steinberg**：经典误差扩散，效果细腻；
- **Atkinson**：只扩散部分误差，对比更强、颗粒更干净（复古像素感）；
- **Bayer**：规则有序抖动，适合想要“编织纹理”风格。

抖动默认关闭——因为拼豆是实体手工，很多玩家更希望**颜色干净、便于采购**，而不是一味追求渐变。

## 色板与色号数据

色号集中维护在 `palettes/*.json`，一个品牌一份，方便扩展与校验：

```json
{
  "brand": "hama",
  "colors": [
    { "code": "H01", "name": "White", "rgb": [255, 255, 255] },
    { "code": "H02", "name": "Cream", "rgb": [255, 240, 210] }
  ]
}
```

目前已支持 Hama / Perler / Artkal / Mard / COCO 等品牌，`max_colors` 可限制用色数量（在品牌色板内选子集），直接决定“要买多少种颜色”。

## 参数化才是核心卖点

转化接口把参数分成几组，全部可调、可存快照、可复现：

```json
{
  "input_mode": "beads",
  "grid_width": 58,
  "grid_height": 58,
  "palette": "hama",
  "max_colors": 24,
  "quantizer": "nearest",
  "dither": { "enabled": false, "algorithm": "floyd_steinberg", "strength": 0.8 },
  "remove_background": { "enabled": true, "mode": "auto" },
  "render": { "bead_style": "round", "show_grid": true, "show_labels": true }
}
```

其中**去背景**支持两种模式：纯色吸管抠除（快、可控）与 `rembg` 自动抠图（省事）。对拼豆来说，抠干净背景往往比任何滤镜都重要。

## 性能与幂等

- 单张 100×100 网格量化基本 < 1s，含抖动/渲染 < 3s；
- CPU 密集计算放进程池隔离，避免阻塞事件循环；
- 大图先降采样；
- **同图 + 同参数可缓存结果**，天然幂等，重复请求不再重算。

## 小结

拼豆图纸的好坏，往往不取决于用多花哨的算法，而在于**是否把“可调参数”和“色号可采购性”考虑清楚**。让玩家能一眼看懂“这张图要用哪几种色、各多少颗豆”，比追求极致渐变更有价值。
